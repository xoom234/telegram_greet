# Телеграм-бот склада табака — инструкция по реализации

Документ описывает, как построить бота, который пишет приходы и расходы в Google Таблицу
`sklad_tabak`, считает остатки и показывает, кто и когда вносил позиции.

---

## 0. Что уже готово в проекте

| Компонент | Файл | Состояние |
|---|---|---|
| Доступ к Google Sheets | `sheets/client.py` | Работает, сервисный аккаунт подключён |
| Проверка связи | `sheets/check_connection.py` | Работает |
| Таблица | лист `Накладные` | Колонки A–I заполняются вручную, K–N — служебные формулы |
| Скелет бота | `main.py` | Пока приветствие, будет заменён |

Переменные окружения в `.env`:

```env
BOT_TOKEN=...
SHEET_URL=https://docs.google.com/spreadsheets/d/1fLfkoyvkFgxOsObYGvcbk7M5pC5qCjKWlRzckjZ2zZo/edit
GOOGLE_CREDENTIALS=credentials/credentials.json
```

### Структура листа `Накладные`

| Колонка | Поле | Кто заполняет |
|---|---|---|
| A | Дата | бот |
| B | № накладной | бот (автономер) |
| C | Бренд | бот |
| D | Вкус | бот |
| E | Вид фасовки | бот |
| F | Количество | бот |
| G | Операция (`Приход` / `Расход`) | бот |
| H | Кто внёс | бот |
| I | Комментарий | бот (telegram-ник, id) |
| K–N | `Бренд_чист`, `Вкус_чист`, `Кол_знак`, `Фасовка_чист` | ARRAYFORMULA, **не трогать** |

Листы-справочники: `Бренды` (A4:A103, сейчас 23 бренда), `Фасовки` (A4:A23, 8 фасовок).

> Важно: формулы в K–N живут в строках 4–2000. Бот пишет только A–I и **никогда** не затирает K–N.

|---|---|---|
| `/приход` | `/приход 04.10.2026 Сарма классик Буратино 200 г 10 Федя` | строка в `Накладные` с операцией `Приход` |

## 2. Главная техническая ловушка (прочитать до начала работы)

Telegram **не распознаёт команды на кириллице** как `bot_command`. Сообщение `/приход ...`
приходит обычным текстом, поэтому фильтр `Command("приход")` из aiogram **не сработает**.

Решение: матчить регуляркой по тексту.

```python
from aiogram import F

PRIHOD_RE = r"^/(приход|prihod|in)(\s|$)"
RASHOD_RE = r"^/(расход|рассход|rashod|out)(\s|$)"
OSTATKI_RE = r"^/(остатки|ostatki|stock)(\s|$)"
INFO_RE = r"^/(инфо|info)(\s|$)"

dp.message.register(cmd_prihod, F.text.regexp(PRIHOD_RE))
```

Опечатка `/рассход` поддерживается намеренно — пользователь её уже использует.
Латинские алиасы (`/in`, `/out`, `/stock`, `/info`) нужны, чтобы команды отображались
в меню BotFather: туда можно добавить только латиницу.

## 5. Этап 2 — Слой доступа к таблице (`bot/repository.py`)

### 5.1 Модели данных

```python
@dataclass
class Operation:
    date: datetime.date
    brand: str
    flavor: str
    pack: str
    qty: int
    author: str
    kind: Literal["Приход", "Расход"]
    comment: str = ""

@dataclass
class MovementRow:
    row_number: int
    date: str
    doc_no: str
    brand: str
    flavor: str
    pack: str
    qty: int
    kind: str
    author: str
    comment: str
```

### 5.2 Функции

| Функция | Назначение |
|---|---|
| `load_brands()` | список брендов из `Бренды!A4:A103`, кэш |
| `load_packs()` | список фасовок из `Фасовки!A4:A23`, кэш |
| `read_movements()` | все строки `Накладные!A4:I2000`, пропуская пустые |
| `append_operation(op)` | дописать строку, вернуть номер строки и `№ накладной` |
| `add_brand(name)` | добавить бренд в справочник |
| `next_doc_no()` | следующий номер вида `Н-004` |
| `next_free_row()` | первая строка, где пусто в C (бренд) |

### 5.3 Поиск свободной строки — важная деталь

`worksheet.append_row()` использовать **нельзя**: из-за ARRAYFORMULA в K–N gspread
считает занятыми все строки до 2000 и допишет данные в район 2001-й, где формул уже нет.

Правильно:

```python
def next_free_row(ws) -> int:
    brands_col = ws.col_values(3)  # колонка C
    # первые 3 строки — заголовки
    for idx in range(3, len(brands_col)):
        if not brands_col[idx].strip():
            return idx + 1
    return len(brands_col) + 1
```

Запись — через `ws.update(f"A{row}:I{row}", [[...]], value_input_option="USER_ENTERED")`.

### 5.4 Нормализация

В таблице уже есть мусор: `' 200 г '`, `'Palitra '`, `'Федор '`. Репозиторий всегда
применяет `strip()` и при записи, и при чтении. Пробелы в данных не должны влиять на подсчёт.

### 5.5 Кэш и лимиты API

Google Sheets API: ~60 запросов в минуту на пользователя. Правила:

- справочники брендов и фасовок кэшировать на `CACHE_TTL_SECONDS` (по умолчанию 5 минут);
- `read_movements()` делать **одним** запросом диапазона, не по строкам;
- после `append_operation()` сбрасывать кэш движений;
- все вызовы gspread выполнять через `asyncio.to_thread(...)`, иначе бот будет блокироваться.

### 5.6 Защита от гонок

Две одновременные команды могут записать в одну строку. Решение — один
`asyncio.Lock` на запись в модуле репозитория:

```python
_write_lock = asyncio.Lock()

async def append_operation(op: Operation) -> tuple[int, str]:
    async with _write_lock:
        ...
```

**Критерий готовности этапа:** скрипт пишет тестовую строку, она появляется в таблице
в первой пустой строке, формулы K–N подхватывают её, остаток на листе `Склад` меняется.

## 6. Этап 3 — Парсер команды (`bot/parsing.py`)

Самая сложная часть: бренд и вкус состоят из нескольких слов, фасовка содержит пробел
(`200 г`). Поэтому дробить строку по пробелам нельзя.

### 6.1 Алгоритм разбора

Вход: `04.10.2026 Сарма классик Буратино 200 г 10 Федя`

1. **Дата** — регулярка `^(\d{2}\.\d{2}\.\d{4})` в начале. Если даты нет, берётся сегодняшняя,
   а остаток строки разбирается дальше. Поддержать слова `сегодня`, `вчера`.
2. **Фасовка** — искать по справочнику фасовок. Регулярка собирается из
   `load_packs()`: `(25|30|40|50|100|125|200|250)\s*г`. Берётся **последнее** совпадение,
   чтобы `100 г` во вкусе не ломало разбор.
3. **Количество** — первое целое число **после** фасовки.
4. **Кто внёс** — всё, что осталось после количества. Если пусто — `DEFAULT_AUTHOR`.
5. **Бренд + вкус** — текст между датой и фасовкой. Бренд определяется по справочнику:
   берётся самое длинное название из `load_brands()`, которым начинается этот фрагмент.
   Остаток — вкус.

### 6.2 Почему бренд ищется по справочнику

`Сарма классик Буратино` нельзя разделить по количеству слов: есть бренды из одного слова
(`Darkside`), из двух (`Сарма классик`) и даже с уточнением (`Хулиган классический`).
Единственный надёжный путь — сопоставление со списком брендов, от длинных к коротким.

### 6.3 Нечёткое совпадение

Если точного совпадения нет, использовать `rapidfuzz.process.extractOne` с порогом 85.
При совпадении 85–95 — переспросить кнопкой «Да, это Сарма классик / Отмена».
Ниже 85 — предложить создать новый бренд.

### 6.4 Поддержка кавычек

Разрешить явный синтаксис, снимающий любую неоднозначность:

```
/приход 04.10.2026 "Сарма классик" "Буратино" 200 г 10 Федя
```

Если в строке есть кавычки — парсить по ним, справочник не нужен.

### 6.5 Ошибки парсера

Возвращать не исключение, а объект с понятным текстом:

| Ситуация | Текст ответа |
|---|---|
| Не найдена фасовка | «Не понял фасовку. Доступные: 25 г, 30 г, 40 г, 50 г, 100 г, 125 г, 200 г, 250 г» |
| Нет количества | «Не вижу количество. Пример: `/приход 04.10.2026 Сарма классик Буратино 200 г 10 Федя`» |
| Неизвестный бренд | «Бренд «X» не найден. Добавить его в справочник?» + кнопки |
| Количество ≤ 0 | «Количество должно быть больше нуля» |

### 6.6 Тесты парсера (`tests/test_parsing.py`)

Обязательные кейсы:

```python
"04.10.2026 Сарма классик Буратино 200 г 10 Федя"   # базовый
"Сарма классик Буратино 200 г 10 Федя"              # без даты
"04.10.2026 Darkside Cosmo Flower 50г 3 Федя"       # без пробела в фасовке
"04.10.2026 Хулиган классический Мята 100 г 1"      # без автора
'04.10.2026 "Сарма классик" "Буратино" 200 г 10'    # кавычки
"04.10.2026 Сарма клссик Буратино 200 г 10 Федя"    # опечатка → fuzzy
"сегодня Afzal Limon-Lime 40 г 20 Федя"             # слово вместо даты
```

**Критерий готовности этапа:** `pytest tests/test_parsing.py` зелёный, таблица не нужна.

## 7. Этап 4 — Команда `/приход`

Файл `bot/handlers/movement.py`.

Последовательность:

1. Проверить доступ (middleware).
2. Отрезать саму команду, передать остаток в парсер.
3. При ошибке — отправить текст ошибки и пример, выйти.
4. Если бренд неизвестен — предложить inline-кнопки «Добавить бренд» / «Отмена».
5. Собрать `Operation(kind="Приход")`, в `comment` положить `@username id=123456789`.
6. Вызвать `append_operation()`.
7. Ответить подтверждением.

Шаблон ответа:

```
Приход записан
Бренд: Сарма классик
Вкус: Буратино
Фасовка: 200 г
Количество: +10
Дата: 04.10.2026
Внёс: Федя
Накладная: Н-004 (строка 9)
```

**Критерий готовности:** команда из Telegram создаёт строку в таблице, остаток на листе
`Склад` вырастает на 10.

## 8. Этап 5 — Команда `/расход`

Отличия от `/приход`:

1. `kind="Расход"` — в колонку G пишется `Расход`, формула `Кол_знак` сама поставит минус.
2. **Проверка остатка перед записью.** Считать текущий остаток по тройке
   бренд + вкус + фасовка из `read_movements()`.
3. Если расход больше остатка — не писать молча, а предупредить:

```
Внимание: остаток Сарма классик / Буратино / 200 г = 4 шт,
вы списываете 10 шт. Остаток станет -6.
Подтвердите списание.
[ Списать всё равно ]  [ Отмена ]
```

Решение по умолчанию — спрашивать подтверждение, а не блокировать: в реальном складе
бывают незанесённые приходы.

4. Если позиции вообще нет в истории — сообщить «Такой позиции на складе не было»
   и тоже спросить подтверждение.

**Критерий готовности:** расход уменьшает остаток; попытка списать больше остатка
вызывает запрос подтверждения.

## 9. Этап 6 — Команда `/остатки`

Файл `bot/handlers/reports.py`.

### 9.1 Расчёт в Python, а не чтение листа `Склад`

Остатки считать самостоятельно из `Накладные`: лист `Склад` — это визуальный отчёт,
его разметка может измениться, а формулы читать через API неудобно.

```python
balances: dict[tuple[str, str, str], int] = defaultdict(int)
for row in read_movements():
    key = (row.brand, row.flavor, row.pack)
    balances[key] += row.qty if row.kind == "Приход" else -row.qty
```

### 9.2 `/остатки` без аргумента

Краткий отчёт: только бренды с ненулевым остатком, по фасовкам.

```
Остатки на складе

Afzal
  Limon-Lime: 40 г — 20

Palitra
  Sur Dari: 200 г — 0

Сарма классик
  Буратино: 200 г — 10

Всего позиций: 3 | Всего единиц: 30
```

Позиции с нулём показывать отдельным блоком «Нулевые остатки: 1» или скрывать —
по умолчанию скрывать, упоминая количество.

### 9.3 `/остатки Сарма классик`

Фильтр по бренду (с тем же fuzzy-поиском). Подробный вид:

```
Сарма классик

Буратино
  200 г — 10
Итого по бренду: 10 единиц
```

Если бренд не найден — показать 3 ближайших варианта.

### 9.4 Длинные сообщения

Лимит Telegram — 4096 символов. При 23 брендах отчёт может не поместиться.
Разбивать по брендам на несколько сообщений, не рвать строку посередине.

**Критерий готовности:** `/остатки` и `/остатки <бренд>` отдают корректные числа,
совпадающие с листом `Склад`.

## 10. Этап 7 — Команда `/инфо`

### 10.1 `/инфо 05.09.2026`

Фильтр `read_movements()` по колонке A, группировка по автору.

```
05.09.2026

Федя — 3 операции
  + Сарма классик / Буратино / 200 г — 10
  + Afzal / Limon-Lime / 40 г — 20
  − Palitra / Sur Dari / 200 г — 5

Итого: приход 30, расход 5
```

### 10.2 Варианты вызова

| Вызов | Поведение |
|---|---|
| `/инфо` | сегодняшняя дата |
| `/инфо 05.09.2026` | конкретный день |
| `/инфо Федя` | все операции этого автора за последние 30 дней |
| `/инфо 01.09.2026 30.09.2026` | диапазон дат |

### 10.3 Пустые даты в таблице

В строках 7–8 листа `Накладные` дата и автор не заполнены. Такие записи выводить
в блоке «Без даты: N записей» и не терять. Сам бот всегда пишет дату и автора,
поэтому проблема только с историей, занесённой руками.

**Критерий готовности:** команда показывает операции за указанный день с разбивкой по людям.

## 11. Этап 8 — Диалоговый режим (fallback)

Если парсер не справился дважды или пользователь прислал просто `/приход`, включать
пошаговый ввод через `aiogram.fsm`:

```
Бренд? → кнопки с 23 брендами (по 2 в ряд) + «Другой»
Вкус? → текстом
Фасовка? → кнопки 25 г … 250 г
Количество? → текстом, только число
Кто вносит? → кнопка «Федя» + «Другое имя»
Проверьте: … [ Записать ] [ Отмена ]
```

Состояния: `MovementForm.brand / flavor / pack / qty / author / confirm`.
Хранилище — `MemoryStorage` достаточно; при перезапуске незавершённые диалоги теряются,
это допустимо.

Обязательно: команда `/отмена` сбрасывает любое состояние.

**Критерий готовности:** ввод позиции целиком кнопками, без ручного набора строки.

## 12. Этап 9 — Ошибки, логи, устойчивость

| Проблема | Обработка |
|---|---|
| Google API 429 (лимит) | retry с экспоненциальной задержкой 1 с → 2 с → 4 с, затем «Таблица занята, повторите» |
| Нет сети | «Не могу подключиться к таблице», лог с трейсбеком |
| Отозван доступ сервисного аккаунта | «Нет доступа к таблице. Проверьте, что доступ Редактор выдан phomoikahoomgera@original-frame-510609-i7.iam.gserviceaccount.com» |
| Любое исключение в хендлере | глобальный `errors` handler: пользователю — короткий текст, в лог — трейсбек |

Логи: `logging` в файл `logs/bot.log` с ротацией, уровень INFO.
Каждую записанную операцию логировать строкой
`APPEND row=9 Приход Сарма классик/Буратино/200 г qty=10 by=Федя tg=123456789`.

## 13. Этап 10 — Тесты и приёмка

### 13.2 Ручная приёмка на реальной таблице

Выполнить последовательно и сверять лист `Склад`:

1. `/приход 04.10.2026 Сарма классик Буратино 200 г 10 Федя` → остаток 200 г = 10 (было 10, станет 20).
2. `/расход 04.10.2026 Сарма классик Буратино 200 г 5 Федя` → остаток уменьшился на 5.
3. `/расход 04.10.2026 Сарма классик Буратино 200 г 9999 Федя` → запрос подтверждения.
4. `/остатки` → в отчёте есть Сарма классик с верным числом.
5. `/остатки Сарма классик` → только этот бренд.
6. `/инфо 04.10.2026` → видно Федю и все операции выше.
7. `/приход` без параметров → включился пошаговый диалог.
8. Команда от постороннего аккаунта → «Нет доступа».

## 15. Порядок работ

| Этап | Результат | Можно проверить без Telegram |
|---|---|---|
| 1. Конфиг | `bot/config.py`, `.env` | да |
| 2. Репозиторий | запись и чтение `Накладные` | да, скриптом |
| 3. Парсер | `bot/parsing.py` + тесты | да, pytest |
| 4. `/приход` | запись из чата | нет |
| 5. `/расход` | запись + проверка остатка | нет |
| 6. `/остатки` | отчёты | нет |
| 7. `/инфо` | отчёт по людям и датам | нет |
| 8. FSM-диалог | ввод кнопками | нет |
| 9. Ошибки и логи | устойчивость | частично |
| 10. Тесты и приёмка | чек-лист из 13.2 | частично |
| 11. Автозапуск | launchd | да |

Этапы 1–3 дают работающее ядро без Telegram и закрывают большую часть риска:
если парсер и запись в таблицу надёжны, остальное — обвязка.

## 16. Решения, которые стоит подтвердить до кодирования

1. **Отрицательные остатки** — разрешить с подтверждением (предложенный вариант)
   или жёстко запрещать.
2. **Новые бренды и вкусы из чата** — добавлять в справочник автоматически
   или только после подтверждения кнопкой (предложенный вариант).
3. **Доступ** — только ты, или список сотрудников с правом записи.
4. **Фасовки** — фиксированный список из 8 значений, или бот может добавлять новые.
5. **Номер накладной** — автонумерация `Н-004` или ввод номера в команде.
